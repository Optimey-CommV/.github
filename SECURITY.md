# Security policy

This policy covers every repository under [github.com/Optimey-CommV](https://github.com/Optimey-CommV) that does not have its own SECURITY.md.

## Reporting a vulnerability

Please do not report security problems in public issues, discussions or pull requests.

Report privately instead: open the **Security and quality** tab of the repository and choose **Report a vulnerability**. If that option is missing, mail [joost@optimey.be](mailto:joost@optimey.be) with SECURITY in the subject line.

A useful report names the affected repository and version or commit, explains what an attacker can achieve and under which conditions, and includes the steps or a proof of concept to reproduce it.

## What to expect

Optimey is a one-person company, so these are targets, not guarantees:

- acknowledgement within 5 working days
- a first assessment within 14 days
- for confirmed issues, a fix or mitigation, agreed with you before anything is disclosed

Reporters are credited in the published advisory, unless they prefer to stay anonymous.

## Supported versions

Security fixes go into the latest release of each project. Older releases are not patched unless the project's README says otherwise.

## Scope

In scope is the code in these repositories. Please do not test against systems you do not own or have no permission to test, and leave out denial of service and social engineering.
